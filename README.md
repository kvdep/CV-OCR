# im2latex-cv-transformer

Автономная модульная система оптического распознавания математических формул LaTeX по изображениям (Image-to-LaTeX OCR) на базе гибридной архитектуры: сверточный энкодер с блоками C3k2 (CSP) и C2PSA (Position-Sensitive Attention) + авторегрессионный декодер на базе Transformer с FlashAttention и синтаксическими ограничениями.

---

## 1. Постановка задачи и спецификация данных

### 1.1. Математическая формулировка
Задача sequence-to-sequence заключается в отображении двумерного растрового изображения математического выражения:
$$X \in \mathbb{R}^{1 \times H \times W}$$
в одномерную дискретную последовательность токенов языка разметки LaTeX:
$$Y = (y_1, y_2, \dots, y_T), \quad y_t \in V$$
где $V$ — дискретный словарь токенов формул, расширенный служебными символами:
- `<P>` (Padding, заполнитель батча)
- `<S>` (Start of sequence, маркер начала генерации)
- `<E>` (End of sequence, маркер завершения генерации)
- `<UNK>` (Unknown token, неизвестный токен)

### 1.2. Предобработка изображений
Входные изображения приводятся к фиксированному тензору размера $(C=1, H=128, W=1024)$ по следующему алгоритму:
1. **Инверсия фона**: для изображения $I$ в градациях серого вычисляется средняя интенсивность пикселей:
   $$\bar{I} = \frac{1}{H_{orig} \cdot W_{orig}} \sum_{i=1}^{H_{orig}} \sum_{j=1}^{W_{orig}} I_{i,j}$$
   Если $\bar{I} > 127$ (темные символы на светлом фоне), применяется инверсия:
   $$I_{inv} = 255 - I$$
2. **Пропорциональное масштабирование**: масштабный коэффициент вычисляется с сохранением исходного соотношения сторон:
   $$s = \min\left(\frac{1024}{W_{orig}}, \frac{128}{H_{orig}}\right)$$
   Новые размеры: $W_{new} = \lfloor W_{orig} \cdot s \rfloor$, $H_{new} = \lfloor H_{orig} \cdot s \rfloor$. Масштабирование выполняется билинейной интерполяцией.
3. **Паддинг на холст**: масштабированное изображение вставляется в координаты $(0, 0)$ черного холста $1024 \times 128$.
4. **Стандартизация**:
   $$\hat{X} = \frac{X / 255.0 - \mu}{\sigma}, \quad \mu = 0.0672, \; \sigma = 0.1625$$

### 1.3. Синтаксическая нормализация и токенизация LaTeX
Перед построением словаря и обучением формулы проходят детерминированную стандартизацию:
- Удаление однострочных комментариев TeX (`% ...`).
- Трансляция устаревших шрифтовых команд в синтаксис LaTeX2e:
  `\rm` $\to$ `\mathrm`, `\bf` $\to$ `\mathbf`, `\it` $\to$ `\mathit`, `\cal` $\to$ `\mathcal`, `\sf` $\to$ `\mathsf`, `\tt` $\to$ `\mathtt`.
- Унификация дробных выражений: замена `{num \over denom}` на `\frac{num}{denom}`, замена `\dfrac` и `\tfrac` на `\frac`.
- Приведение индексов к блочной нотации: `_a` $\to$ `_{a}`, `^a` $\to$ `^{a}`.
- Нормализация порядка следования индексов: $X^{\{b\}}_{\{a\}} \to X_{\{a\}}^{\{b\}}$.
- Удаление избыточных вложенных фигурных скобок: `{{expr}}` $\to$ `{expr}`.
- Замена пробельных команд TeX (`\,`, `\:`, `\;`, `\!`, `\quad`, `\qquad`, `~`) на пробелы.
- Токенизация регулярным выражением:
  `\\[a-zA-Z]+|\\[^a-zA-Z]|\d|[a-zA-Z]|[^ \t\n\r\f\v]`

## 2. Архитектура нейросети

Модель `FlexibleCNNTransformer` состоит из сверточного энкодера с механизмами разделения каналов и авторегрессионного декодера.

```
Входное изображение: [B, 1, 128, 1024]
        │
        ▼
   [Stem Conv]          --> [B, 64, 64, 512]
        │
        ▼
[Stage 1: C3k2 + Pool]  --> [B, 128, 32, 256]
        │
        ▼
[Stage 2: C3k2 + Pool]  --> [B, 256, 16, 128]
        │
        ▼
[Stage 3: C3k2 + Pool]  --> [B, 256, 16, 128]
        │
        ▼
   [Stage 4: C3k2]      --> [B, 256, 16, 128]
        │
        ▼
   [PSA: C2PSA]         --> [B, 256, 16, 128]
        │
        ▼
 [Fusion 1x1 + 2D PE]   --> [B, 256, 16, 128]
        │
        ▼
 [Flatten & LayerNorm]  --> Memory: [B, 2048, 256]
        │
        ▼
[FlashDecoder: 8 слоев] <── Target Tokens + 1D PE: [B, T, 256]
        │
        ▼
[Linear: 256 -> |V|]    --> Logits: [B, T, |V|]
```

### 2.1. Спецификация слоев энкодера

| Блок | Тип операции | Входная размерность | Выходная размерность | Параметры |
|---|---|---|---|---|
| **Stem 1** | `Conv2d + BN + SiLU` | $[B, 1, 128, 1024]$ | $[B, 32, 64, 512]$ | $k=3, s=2, p=1$ |
| **Stem 2** | `Conv2d + BN + SiLU` | $[B, 32, 64, 512]$ | $[B, 64, 64, 512]$ | $k=3, s=1, p=1$ |
| **Stage 1** | `C3k2 (CSP)` | $[B, 64, 64, 512]$ | $[B, 128, 64, 512]$ | $n=2, e=0.5, \text{shortcut}=\text{True}$ |
| **Pool 1** | `MaxPool2d` | $[B, 128, 64, 512]$ | $[B, 128, 32, 256]$ | $k=(2, 2), s=(2, 2)$ |
| **Stage 2** | `C3k2 (CSP)` | $[B, 128, 32, 256]$ | $[B, 256, 32, 256]$ | $n=2, e=0.5, \text{shortcut}=\text{True}$ |
| **Pool 2** | `MaxPool2d` | $[B, 256, 32, 256]$ | $[B, 256, 16, 128]$ | $k=(2, 2), s=(2, 2)$ |
| **Stage 3** | `C3k2 (CSP)` | $[B, 256, 16, 128]$ | $[B, 256, 16, 128]$ | $n=3, e=0.5, \text{shortcut}=\text{True}$ |
| **Pool 3** | `MaxPool2d` | $[B, 256, 16, 128]$ | $[B, 256, 16, 128]$ | $k=(1, 1), s=(1, 1)$ |
| **Stage 4** | `C3k2 (CSP)` | $[B, 256, 16, 128]$ | $[B, 256, 16, 128]$ | $n=3, e=0.5, \text{shortcut}=\text{True}$ |
| **PSA** | `C2PSA + Conv` | $[B, 256, 16, 128]$ | $[B, 256, 16, 128]$ | $n=2, \text{heads}=4$ |
| **Fusion** | `Conv2d 1x1` | $[B, 256, 16, 128]$ | $[B, 256, 16, 128]$ | $k=1, s=1, d_{model}=256$ |

### 2.2. Двумерное позиционное кодирование (2D Positional Encoding)
Для сохранения геометрического расположения символов к выходной карте признаков энкодера применяется 2D синусоидальное кодирование. Каналы $d_{model} = 256$ разделяются пополам:
- Первые 128 каналов кодируют координату по горизонтали $w \in [0, 127]$:
  $$PE_{(2i, h, w)} = \sin\left(\frac{w}{10000^{2i / 128}}\right), \quad PE_{(2i+1, h, w)} = \cos\left(\frac{w}{10000^{2i / 128}}\right), \quad i \in [0, 63]$$
- Вторые 128 каналов кодируют координату по вертикали $h \in [0, 15]$:
  $$PE_{(128 + 2i, h, w)} = \sin\left(\frac{h}{10000^{2i / 128}}\right), \quad PE_{(128 + 2i+1, h, w)} = \cos\left(\frac{h}{10000^{2i / 128}}\right), \quad i \in [0, 63]$$

Результирующий тензор разворачивается в последовательность визуальных токенов:
$$\text{Memory} \in \mathbb{R}^{B \times 2048 \times 256}, \quad 2048 = 16 \times 128$$

### 2.3. Спецификация авторегрессионного декодера (FlashDecoderLayer)
Декодер состоит из 8 последовательных слоев `FlashDecoderLayer`. Внутри каждого слоя реализована архитектура Pre-LayerNorm:
1. **Masked Self-Attention**:
   $$\text{Attention}(Q, K, V) = \text{softmax}\left(\frac{QK^T}{\sqrt{d_k}} + M_{causal}\right)V$$
   где $d_k = d_{model} / nhead = 256 / 8 = 32$. Вычисление выполняется через `torch.nn.functional.scaled_dot_product_attention` (FlashAttention).
2. **Cross-Attention**: запросы $Q$ вычисляются из промежуточных представлений текста, а ключи $K$ и значения $V$ — из визуальной памяти $\text{Memory}$.
3. **Feed-Forward Network (FFN)**:
   $$\text{FFN}(x) = W_2 \cdot \text{GELU}(W_1 x), \quad W_1 \in \mathbb{R}^{256 \times 1024}, \; W_2 \in \mathbb{R}^{1024 \times 256}$$
4. **KV-кэширование**: при генерации токены генерируются пошагово ($t=1$). Вычисленные проекции $K$ и $V$ сохраняются в словаре `state`, снижая вычислительную сложность генерации шага с $O(T^2)$ до $O(1)$.

## 3. Функция потерь и регуляризация

### 3.1. Кросс-энтропия со сглаживанием меток (Label Smoothing)
Для предотвращения переобучения и избыточной уверенности сети применяется сглаживание целевого распределения с коэффициентом $\epsilon = 0.1$:
$$p_{LS}(k) = (1 - \epsilon) \cdot \mathbb{I}(k = y_t) + \frac{\epsilon}{|V|}$$
Потери для одного токена:
$$\mathcal{L}_{CE}(y_t, \hat{y}_t) = -\sum_{k=1}^{|V|} p_{LS}(k) \log \frac{\exp(z_{t, k})}{\sum_{j=1}^{|V|} \exp(z_{t, j})}$$

### 3.2. Обратное частотное взвешивание классов (Inverse Class Frequency)
Для компенсации дисбаланса частот (символы скобок и цифр встречаются на 2–3 порядка чаще редких операторов) веса вычисляются по обучающему сплиту:
$$f_i = \frac{N_i}{\sum_{k \in V} N_k}$$
$$w_i = \min\left(\frac{1}{f_i + 10^{-5}} \cdot \frac{1}{\min_{j} \frac{1}{f_j + 10^{-5}}}, \text{weight\_ratio}\right), \quad w_{<P>} = 0$$
Итоговые взвешенные потери батча:
$$\mathcal{L}_{weighted} = \frac{\sum_{b=1}^B \sum_{t=1}^T w_{y_{b,t}} \mathcal{L}_{CE}(y_{b,t}, \hat{y}_{b,t})}{\sum_{b=1}^B \sum_{t=1}^T w_{y_{b,t}} + 10^{-8}}$$

### 3.3. Векторизованный штраф за циклы и частотное превышение
В процессе обучения к логитам применяется дифференцируемый квадратичный штраф:
$$\Delta z_{b, t, v} = 2.0 \cdot \max\left(0, \sum_{\tau=1}^t \mathbb{I}(y_{b, \tau} = v) + 1 - \sum_{\tau=1}^T \mathbb{I}(target_{b, \tau} = v)\right)^2$$
Все логиты ограничиваются диапазоном $[-60000.0, 60000.0]$ для предотвращения переполнения в формате FP16.

## 4. Синтаксические ограничения инференса

Во время инференса (жадный поиск или Beam Search) к выходным логитам $\mathbf{z}_t \in \mathbb{R}^{|V|}$ динамически применяются правила грамматики LaTeX:

1. **Запрет пустых скобок**: если $y_{t-1} = \text{`\{`}$, то:
   $$z_{t, \text{`\}`}} \leftarrow z_{t, \text{`\}`}} - 1000.0$$
2. **Штраф за избыточное открытие**: если $y_{t-1} = \text{`\{`}$, то:
   $$z_{t, \text{`\{`}} \leftarrow z_{t, \text{`\{`}} - 2.0 \cdot |z_{t, \text{`\{`}}| - 5.0$$
3. **Баланс скобок**: если накопленное число закрывающих скобок достигло числа открывающих ($\sum \mathbb{I}(y = \text{`\}`}) \ge \sum \mathbb{I}(y = \text{`\{`})$):
   $$z_{t, \text{`\}`}} \leftarrow z_{t, \text{`\}`}} - 1000.0$$
4. **Правила индексов**: после операторов `_` и `^` запрещены повторные операторы индексов и закрывающие скобки:
   $$z_{t, \text{`\_`}} \leftarrow -1000.0, \quad z_{t, \text{`\^`}} \leftarrow -1000.0, \quad z_{t, \text{`\}`}} \leftarrow -1000.0$$
5. **Подавление циклов**: если один и тот же символ генерируется $\ge 3$ шагов подряд:
   $$z_{t, y_{t-1}} \leftarrow z_{t, y_{t-1}} - 50.0$$

### 4.1. Лучевой поиск (Beam Search) с нормализацией длины
Ранжирование гипотез луча $Y$ длины $T$ выполняется по нормализованному логарифму правдоподобия:
$$\text{Score}(Y) = \frac{\sum_{t=1}^T \log P(y_t \mid y_{<t}, X)}{\left(\frac{5 + T}{6}\right)^{0.7}}$$

## 5. Метрики качества

### 5.1. Расстояние Левенштейна (Levenshtein Distance)
Расстояние редактирования между последовательностями $s_1$ длины $N$ и $s_2$ длины $M$ определяется рекурсивно:
$$D_L(i, j) = \begin{cases} 
\max(i, j), & \min(i, j) = 0 \\
\min \begin{cases} 
D_L(i-1, j) + 1 & \text{(удаление)} \\
D_L(i, j-1) + 1 & \text{(вставка)} \\
D_L(i-1, j-1) + \mathbb{I}(s_1[i] \ne s_2[j]) & \text{(замена)}
\end{cases}, & \min(i, j) > 0
\end{cases}$$

### 5.2. Exact Match Rate (EM)
Доля предсказанных формул, посимвольно идентичных эталонным:
$$\text{EM} = \frac{1}{N} \sum_{k=1}^N \mathbb{I}(\hat{s}_k = s_k) \times 100\%$$

### 5.3. Character Error Rate (Micro-CER)
Посимвольная частота ошибок редактирования:
$$\text{Micro-CER} = \frac{\sum_{k=1}^N D_L(\hat{s}_k, s_k)}{\sum_{k=1}^N |s_k|} \times 100\%$$

### 5.4. Token Error Rate (Micro-TER)
Потокеновая частота ошибок редактирования:
$$\text{Micro-TER} = \frac{\sum_{k=1}^N D_L(\text{tokens}(\hat{s}_k), \text{tokens}(s_k))}{\sum_{k=1}^N |\text{tokens}(s_k)|} \times 100\%$$

### 5.5. Edit-based Character Distance Metric (Macro-ECDM)
Метрика нормализованного посимвольного сходства, усредненная по выборке:
$$\text{ECDM}_{\text{char}}(\hat{s}, s) = \max\left(0.0, \, 1.0 - \frac{D_L(\hat{s}, s)}{\max(|\hat{s}|, |s|, 1)}\right)$$
$$\text{Macro-ECDM}_{\text{char}} = \frac{1}{N} \sum_{k=1}^N \text{ECDM}_{\text{char}}(\hat{s}_k, s_k) \times 100\%$$

### 5.6. Edit-based Token Distance Metric (Macro-ECDM Token)
Метрика нормализованного потокенового сходства:
$$\text{ECDM}_{\text{token}}(\hat{s}, s) = \max\left(0.0, \, 1.0 - \frac{D_L(\text{tokens}(\hat{s}), \text{tokens}(s))}{\max(|\text{tokens}(\hat{s})|, |\text{tokens}(s)|, 1)}\right)$$
$$\text{Macro-ECDM}_{\text{token}} = \frac{1}{N} \sum_{k=1}^N \text{ECDM}_{\text{token}}(\hat{s}_k, s_k) \times 100\%$$

## 7. Эволюция разработки, абляционный анализ и эвристики

Разработка системы велась итеративно от наивной базовой модели к устойчиво сходящейся архитектуре через последовательное внедрение индуктивных смещений и оптимизацию представления данных.

### 7.1. Базовая модель (Vanilla CNN + Transformer) и проблема расходимости
Первоначальная конфигурация состояла из стандартного сверточного энкодера и классического Transformer-декодера, обучаемых с нуля с использованием стандартной кросс-энтропии без модификаций функции потерь:
$$\mathcal{L} = -\sum_{t=1}^T \log P(y_t \mid y_{<t}, X)$$
**Результат**: модель не сходилась. Значение функции потерь выходило на плато на ранних эпохах.  
**Анализ причины**: при случайной инициализации весов авторегрессионный декодер коллапсировал в вырожденное состояние — циклическую генерацию тривиальных токенов (паддинг `<P>`, повторяющиеся пустые фигурные скобки `{}` или пробельные разделители). Поскольку в стандартной кросс-энтропии доминирующие классы дают наименьший мгновенный штраф при высокой частоте встречаемости в датасете, градиенты подталкивали сеть к локальному минимуму с нулевой вариативностью выхода.

### 7.2. Внедрение структурных и частотных штрафов
Для вывода оптимизатора из вырожденного оптимума были введены детерминированные штрафы:
1. **Штраф за циклические повторения**: при генерации одного и того же токена $k \ge 3$ раз подряд из его логита вычитается константа $50.0$.
2. **Дифференцируемый квадратичный штраф за избыточность**:
   $$\Delta \mathcal{L}_{excess} = 2.0 \cdot \max\left(0, \sum_{\tau=1}^t \mathbb{I}(y_{\tau} = v) + 1 - \sum_{\tau=1}^T \mathbb{I}(target_{\tau} = v)\right)^2$$
   Если на шаге $t$ модель предсказывает токен $v$, суммарное количество которого в сгенерированном префиксе уже превышает количество этого токена в целевой формуле, логит штрафуется пропорционально квадрату превышения.
3. **Грамматические ограничения на скобки**: логит закрывающей скобки `}` обнуляется ($-\infty$), если текущее количество закрывающих скобок сравнялось с количеством открывающих скобок, а также на шаге непосредственно после открывающей скобки `{` (запрет пустых скобок `{}`).

**Результат**: устранение тривиальных циклов позволило градиентам оптимизировать информативные токены. Процесс обучения начал устойчиво сходиться.

### 7.3. Стандартизация синтаксиса формул датасета
Анализ обучающей выборки Im2Latex выявил фундаментальную проблему вариативности разметки: математически и визуально эквивалентные выражения имеют множество различных синтаксических представлений в коде LaTeX. Например:
- `{a \over b}` vs `\frac{a}{b}` vs `\dfrac{a}{b}` vs `\tfrac{a}{b}`
- `{\rm const}` vs `\mathrm{const}`
- `x_1^2` vs `x^2_1`
- `x_a` vs `x_{a}`
- `{{x}}` vs `{x}`

При обучении сеть получала противоречивый градиентный сигнал: для одинакового визуального паттерна дроби целевой токен мог быть как `\frac`, так и `\over`.  
**Решение**: разработан алгоритм канонизации синтаксиса (`src/dataset/preprocessing.py`), нормализующий все эквивалентные формы к единому каноническому виду LaTeX2e:
1. Приведение всех форм дробей к единому `\frac{A}{B}` через регулярные выражения.
2. Унификация шрифтовых команд (`\rm`, `\bf`, `\it`, `\cal`, `\sf`, `\tt` $\to$ `\mathrm`, `\mathbf` и т.д.).
3. Приведение одиночных индексов к блочной записи с фигурными скобками (`_{...}`, `^{...}`).
4. Унификация порядка следования: нижний индекс всегда предшествует верхнему ($X_{\dots}^{\dots}$).
5. Удаление избыточных пар фигурных скобок `{{...}}` и пробельных команд TeX (`\,`, `~`, `\quad`).

**Результат**: энтропия целевого распределения токенов при фиксированном визуальном входе снизилась, что привело к существенному росту точности сходимости.

### 7.4. Редизайн сверточного энкодера и расширение горла признаков
Исходный энкодер содержал последовательность блоков из архитектуры YOLO с агрессивным пулингом (уменьшение пространственных размеров в 2 раза на каждом блоке).  
**Проблема**: для текста и формул агрессивное сжатие разрушает пространственную структуру. Математические глифы (нижние/верхние индексы, апострофы, диакритические знаки, запятые) занимают область размером от 2 до 6 пикселей. Чрезмерное уменьшение разрешения приводило к тому, что признаки мелких символов полностью размывались и смешивались с соседними символами.  
**Модификации**:
1. Устранены блоки чрезмерного даунсэмплинга: в блоке Stage 3 применен пулинг с ядром $1 \times 1$ и шагом 1 (`MaxPool2d((1, 1), stride=(1, 1))`), а блок Stage 4 оставлен без пулинга.
2. Пространственное разрешение карты признаков на входе в декодер сохранено на уровне $H' = 16, W' = 128$, что формирует $16 \times 128 = 2048$ пространственных векторов признаков размерности $d_{model} = 256$.
3. Интегрирован блок внимания C2PSA (Pointwise / Position-Sensitive Attention с MultiheadAttention на 4 головы) для агрегации контекста между удаленными частями формулы перед передачей в декодер.
4. Добавлено двумерное синусоидальное позиционное кодирование (2D PE), отдельно кодирующее 128 каналов координаты $x$ и 128 каналов координаты $y$.

**Результат**: декодер получил детальную пространственную карту с высоким разрешением по горизонтали ($W'=128$), что позволило модели различать сложные многоуровневые выражения и индексы.

### 7.5. Инверсия изображений и физика сигналов в нейронных сетях
В исходном датасете изображения представлены в стандартном виде: черный текст на белом фоне.  
**Проблема физического представления**:
1. Значения пикселей белого фона близки к 255 ($1.0$ после нормализации), а черных штрихов текста — к 0 ($0.0$).
2. В нейронных сетях со смещениями (bias) и функциями активации ReLU / SiLU нулевое значение тензора трактуется как отсутствие сигнала/активации, а ненулевые положительные значения — как присутствие признака.
3. При нулевом паддинге изображения на холст $1024 \times 128$ граница между белым фоном формулы (255) и черным паддингом (0) создавала мощный паразитный градиентный перепад, сбивающий сверточные фильтры. Текст формулы воспринимался как пропуски/дыры в сплошном поле высокой активности.  
**Решение**: автоматическая инверсия яркости при $\bar{I} > 127$:
$$I_{inv} = 255 - I$$
В результате фон становится строго нулевым ($0$), идеально совпадая с нулевым паддингом холста, а штрихи символов формулы становятся активными положительными значениями ($> 0$).  
В декодере cross-attention дополнительно снабжен бинарной маской наличия глифов:
$$M_{memory} = \text{AdaptiveMaxPool2d}((X > 0), (16, 128))$$

**Результат**: посимвольная метрика сходства **Macro-ECDM выросла до 79.29% (~0.80)**.

### 7.6. Анализ метрик: расхождение Exact Match (~12.8%) и Macro-ECDM (~79.3%)
Метрика Exact Match (EM) составила 12.81%, в то время как посимвольный Macro-ECDM достиг 79.29%, а посимвольная ошибка Micro-CER снизилась до 28.63%.  
**Причина расхождения**:
Автоматическая канонизация синтаксиса LaTeX не решает задачу проверки изоморфизма выражений во всех комбинаторных случаях:
1. Коммутативность операций: выражение $a + b$ визуально и семантически эквивалентно $b + a$, но посимвольно не совпадает.
2. Эквивалентные команды скобок: `\left( ... \right)` визуально идентично `( ... )` для стандартной высоты символов.
3. Неявные операторы умножения: $a \cdot b$ vs $ab$.
4. Эквивалентные макросы: `\ne` vs `\neq`, `\le` vs `\leq`, `\ge` vs `\geq`.
5. Невидимые пробельные интервалы внутри математических окружений.

Модель предсказывает математически эквивалентные, компилируемые формулы, визуально в точности соответствующие исходному изображению. Метрика Exact Match штрафует формулу 0 при любом единичном несовпадении символа разметки, в то время как метрика ECDM отражает реальное высокое качество распознавания математической структуры выражения.

## 9. Инструкция по установке и запуску

### 9.1. Системные требования и окружение
- Python $\ge$ 3.10
- PyTorch $\ge$ 2.0 (с поддержкой CUDA)
- TeX Live или MiKTeX (опционально, для компиляции формул в PNG):
  - **Linux**: `sudo apt update && sudo apt install -y texlive-latex-base texlive-latex-extra dvipng cm-super`
  - **Windows**: установить [MiKTeX](https://miktex.org/) или TeX Live и убедиться, что `latex.exe` и `dvipng.exe` добавлены в системную переменную `PATH`.

Установка зависимостей:
```bash
pip install -r requirements.txt
```

### 9.2. Подготовка данных
Подготовка и очистка сырых сплитов формул с генерацией словаря `custom_t2i.json`:
```bash
python scripts/prepare_data.py --source_dir ./dataset/dataset --target_dir ./dataset/dataset_clean
```

### 9.3. Запуск обучения
Обучение с автоматическим подбором размера батча под доступную видеопамять:
```bash
python scripts/train.py --model_name real_test_model --base_path ./dataset/dataset_clean --num_epochs 150 --lr 1e-4 --weight_ratio 5.0 --label_smoothing 0.1
```

### 9.4. Тестирование и вычисление метрик
Оценка чекпоинта на тестовой выборке с лучевым поиском и формированием сводной таблицы:
```bash
python scripts/evaluate.py --checkpoint ./checkpoints/best_real_test_model.pt --base_path ./dataset/dataset_clean --beam_width 3 --num_visual_samples 10
```

### 9.5. Одиночный инференс
Распознавание формулы с сохранением скомпилированного PNG:
```bash
python scripts/infer.py --image ./test_sample.png --checkpoint ./checkpoints/best_real_test_model.pt --beam_width 3 --render ./pred_render.png
```
