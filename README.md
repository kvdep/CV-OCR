# im2latex-cv-transformer

Распознавание формул LaTeX по изображениям (Image-to-LaTeX OCR).  
**Стек:** PyTorch, CNN (YOLO C3k2, SPPF, C2PSA) + Transformer Decoder (FlashAttention SDPA, KV-кэш, 2D Sinusoidal PE).

### 1.2. Описание метрик: назначение и приоритет

#### Macro-ECDM (Edit-based Character Distance Metric) — ПРИОРИТЕТНАЯ МЕТРИКА

$$
\text{ECDM}_{\text{char}}(\hat{s}, s) = \max\left(0.0, \; 1.0 - \frac{D_L(\hat{s}, s)}{\max(|\hat{s}|, |s|, 1)}\right)
$$

$$
\text{Macro-ECDM}_{\text{char}} = \frac{1}{N} \sum_{k=1}^N \text{ECDM}_{\text{char}}(\hat{s}_k, s_k) \times 100\%
$$

где $D_L(\hat{s}, s)$ — расстояние Левенштейна.

- **Зачем введена**: В LaTeX одна и та же формула записывается множеством синтаксически различных, но математически и визуально тождественных способов ($a+b \equiv b+a$, `\frac{a}{b}` против `{a \over b}`, `\left( \right)` против `()`, невидимые умножения, эквивалентные пробелы).
- **Почему приоритетная**: Строгие бинарные метрики ставят 0 за малейшее косметическое несовпадение кода, даже если скомпилированное выражение визуально идентично на 100%. Macro-ECDM оценивает непрерывную долю правильно предсказанной структуры и символов. Значение **ECDM ~ 80% (79.29% - 80%+)** подтверждает, что сеть устойчиво распознает структуру выражения и глифы.

#### Exact Match (EM)

$$
\text{EM} = \frac{1}{N} \sum_{k=1}^N \mathbb{I}(\hat{s}_k = s_k) \times 100\%
$$

- **Зачем введена**: Классический жесткий бенчмарк строгой посимвольной идентичности строк (12.81%).
- **Почему вторична**: 100% автоматическая канонизация TeX-синтаксиса алгоритмически неразрешима из-за комбинаторного взрыва эквивалентных записей. Поэтому EM занижен относительно визуального качества формул (модель часто пишет правильную формулу, но с эквивалентной вариацией синтаксиса).

#### Micro-CER (Character Error Rate)

$$
\text{Micro-CER} = \frac{\sum_{k=1}^N D_L(\hat{s}_k, s_k)}{\sum_{k=1}^N |s_k|} \times 100\%
$$

- **Зачем введена**: Показывает суммарную долю ошибок (вставки, удаления, замены) на уровне всех символов датасета (28.63%).

#### Micro-TER (Token Error Rate)

$$
\text{Micro-TER} = \frac{\sum_{k=1}^N D_L(\text{tokens}(\hat{s}_k), \text{tokens}(s_k))}{\sum_{k=1}^N |\text{tokens}(s_k)|} \times 100\%
$$

- **Зачем введена**: Считает ошибки не по буквам, а по неделимым токенам TeX (`\frac`, `\alpha`, `^`, `{`, `}`). Показывает, ошибается ли сеть в операторах или в переменных.

#### Test Loss
Кросс-энтропия с Label Smoothing ($\epsilon = 0.1$) и частотным взвешиванием классов (0.6514).

## 2. Архитектура нейросети

Модель `FlexibleCNNTransformer`: сверточный бэкбон (блоки YOLO C3k2, SPPF, C2PSA) + 8 слоев Transformer Decoder с FlashAttention и KV-кэшем.

### 2.1. Спецификация энкодера (CNN Backbone + Attention)

| Блок | Слой / Операция | Вход $[B, C, H, W]$ | Выход $[B, C, H, W]$ | Параметры |
|---|---|---|---|---|
| **Stem 1** | `Conv2d + BN + SiLU` | $[B, 1, 128, 1024]$ | $[B, 32, 64, 512]$ | $k=3, s=2, p=1$ |
| **Stem 2** | `Conv2d + BN + SiLU` | $[B, 32, 64, 512]$ | $[B, 64, 64, 512]$ | $k=3, s=1, p=1$ |
| **Stage 1** | `C3k2` (CSP блок) | $[B, 64, 64, 512]$ | $[B, 128, 64, 512]$ | $n=2, e=0.5, \text{shortcut}=\text{True}$ |
| **Pool 1** | `MaxPool2d` | $[B, 128, 64, 512]$ | $[B, 128, 32, 256]$ | $k=(2, 2), s=(2, 2)$ |
| **Stage 2** | `C3k2` (CSP блок) | $[B, 128, 32, 256]$ | $[B, 256, 32, 256]$ | $n=2, e=0.5, \text{shortcut}=\text{True}$ |
| **Pool 2** | `MaxPool2d` | $[B, 256, 32, 256]$ | $[B, 256, 16, 128]$ | $k=(2, 2), s=(2, 2)$ |
| **Stage 3** | `C3k2` (CSP блок) | $[B, 256, 16, 128]$ | $[B, 256, 16, 128]$ | $n=3, e=0.5, \text{shortcut}=\text{True}$ |
| **Pool 3** | `MaxPool2d` | $[B, 256, 16, 128]$ | $[B, 256, 16, 128]$ | $k=(1, 1), s=(1, 1)$ (без даунсэмплинга) |
| **Stage 4** | `C3k2` (CSP блок) | $[B, 256, 16, 128]$ | $[B, 256, 16, 128]$ | $n=3, e=0.5, \text{shortcut}=\text{True}$ |
| **PSABlock** | `C2PSA` + `Conv` | $[B, 256, 16, 128]$ | $[B, 256, 16, 128]$ | $n=2, \text{heads}=4, e=0.5$ |
| **Fusion** | `Conv2d 1x1` | $[B, 256, 16, 128]$ | $[B, 256, 16, 128]$ | $k=1, s=1, d_{\text{model}}=256$ |
| **2D PE** | `PositionalEncoding2D` | $[B, 256, 16, 128]$ | $[B, 256, 16, 128]$ | 128 каналов на W, 128 каналов на H |
| **Reshape** | `flatten(2).transpose(1, 2)` + `LN` | $[B, 256, 16, 128]$ | $[B, 2048, 256]$ | $2048 = 16 \times 128$ визуальных токенов |

### 2.2. Двумерный позиционный эмбеддинг (2D Positional Encoding)
Вектор $d_{\text{model}} = 256$ делится пополам: 128 каналов кодируют координату $w \in [0, 127]$, 128 каналов — координату $h \in [0, 15]$:

$$
PE_{(2i, h, w)} = \sin\left(\frac{w}{10000^{2i / 128}}\right), \quad PE_{(2i+1, h, w)} = \cos\left(\frac{w}{10000^{2i / 128}}\right)
$$

$$
PE_{(128 + 2i, h, w)} = \sin\left(\frac{h}{10000^{2i / 128}}\right), \quad PE_{(128 + 2i+1, h, w)} = \cos\left(\frac{h}{10000^{2i / 128}}\right)
$$

Выходной тензор памяти энкодера:

$$
\text{Memory} \in \mathbb{R}^{B \times 2048 \times 256}
$$

### 2.3. Спецификация декодера (FlashDecoder)

Декодер содержит стек из 8 слоев `FlashDecoderLayer` с Pre-LayerNorm, FlashAttention (`F.scaled_dot_product_attention`) и KV-кэшем.

| Слой / Подблок | Операция | Входной тензор | Выходной тензор | Параметры |
|---|---|---|---|---|
| **Embedding** | `nn.Embedding` | $[B, T]$ | $[B, T, 256]$ | $d_{\text{model}}=256, \; \|V\| = \text{vocab\_size}$ |
| **1D PE** | `PositionalEncoding` | $[B, T, 256]$ | $[B, T, 256]$ | Синусоидальный PE, $max\_len=2048$ |
| **8x Decoder Layer** | `FlashDecoderLayer`: | | | $N=8, d_{\text{model}}=256, nhead=8$ |
| ├─ *Sublayer 1* | `LN` + Masked Self-Attention | $[B, T, 256]$ | $[B, T, 256]$ | $d_k=32$, Causal Mask, Self KV-cache, Residual, Drop 0.1 |
| ├─ *Sublayer 2* | `LN` + Cross-Attention | $[B, T, 256]$, $\text{Memory}$ | $[B, T, 256]$ | Q из декодера, K/V из $[B, 2048, 256]$, Cross KV-cache |
| └─ *Sublayer 3* | `LN` + FFN (`Linear` -> `GELU` -> `Linear`) | $[B, T, 256]$ | $[B, T, 256]$ | $d_{ff}=1024$, Residual, Drop 0.1 |
| **Final LN** | `nn.LayerNorm` | $[B, T, 256]$ | $[B, T, 256]$ | Нормализация выхода последнего слоя |
| **Linear Head** | `nn.Linear` | $[B, T, 256]$ | $[B, T, |V|]$ | Инициализация Xavier Uniform |

В инференсе $Q$ считается только для текущего токена ($t=1$), а ключи $K$ и значения $V$ берутся из словаря состояний `state`. Сложность шага — $O(1)$ вместо $O(T^2)$.

## 3. Эволюция разработки и эвристики (как получили ECDM 0.8)

### 3.1. Базовый бейзлайн (CNN + Transformer) и расходимость
Сначала взяли стандартный сверточный энкодер и классический трансформер-декодер без дополнительных эвристик и обучали с нуля на обычной кросс-энтропии:

$$
\mathcal{L} = -\sum_{t=1}^T \log P(y_t \mid y_{<t}, X)
$$

**Результат**: модель не сходилась. Лосс быстро выходил на плато.  
**Причина**: декодер сваливался в паразитное предсказание пустоты (паддинг, повторяющиеся скобки `{}` или пробелы). В обычной кросс-энтропии частые классы не штрафуются за повторы, и градиенты загоняли сеть в тривиальный локальный минимум с нулевой вариативностью.

### 3.2. Структурные штрафы
Чтобы выбить оптимизатор из тривиального минимума, добавили детерминированные штрафы:
1. Запрет циклических повторов: вычитание $50.0$ из логита токена при трех повторах подряд.
2. Квадратичный штраф за превышение частоты символа относительно таргета:

$$
\Delta \mathcal{L}_{\text{excess}} = 2.0 \cdot \max\left(0, \sum_{\tau=1}^t \mathbb{I}(y_{\tau} = v) + 1 - \sum_{\tau=1}^T \mathbb{I}(\text{target}_{\tau} = v)\right)^2
$$

3. Запрет закрытия пустых скобок `{}` (маскирование логита на $-1000.0$) и запрет закрытия при превышении числа открытых.

**Результат**: паразитные циклы исчезли, сеть начала обучаться и лосс пошел вниз.

### 3.3. Чистка и стандартизация датасета
В Im2Latex одна и та же формула записана десятком разных вариантов:
- Дроби: `{a \over b}` против `\frac{a}{b}`, `\dfrac{a}{b}`, `\tfrac{a}{b}`
- Шрифты: `{\rm const}` против `\mathrm{const}`
- Индексы: `x_1^2` против `x^2_1`, `x_a` против `x_{a}`
- Лишние фигурные скобки: `{{x}}` против `{x}`

Сеть видела одну и ту же картинку, но получала противоречивые таргеты (например, то `\over`, то `\frac`).  
**Решение**: написан парсер канонизации синтаксиса (`src/dataset/preprocessing.py`), приводящий все формулы к единому стандарту LaTeX2e:
1. Замена `\over`, `\dfrac`, `\tfrac` на `\frac`.
2. Замена устаревших команд шрифтов на `\mathrm`, `\mathbf` и т.д.
3. Оборачивание одинарных индексов в `{}` и фиксация порядка: нижний индекс всегда перед верхним.
4. Вычистка дублирующихся скобок `{{...}}` и пробелов TeX.

**Результат**: дисперсия таргетов упала, точность предсказания выросла.

### 3.4. Редизайн энкодера и расширение горла
В исходном энкодере стояли стандартные блоки из YOLO с агрессивным даунсэмплингом (пулинг с шагом 2 на каждом блоке).  
**Проблема**: математические глифы (индексы, штрихи, запятые) занимают от 2 до 6 пикселей. Агрессивное сжатие полностью стирало мелкие символы — они превращались в кашу на низком разрешении.  
**Что изменили**:
1. Убрали блоки избыточного даунсэмплинга: на Stage 3 пулинг переведен в ядро $1 \times 1$ с шагом 1 (`MaxPool2d((1, 1), stride=(1, 1))`), а на Stage 4 пулинг полностью убран.
2. Расширили горло из свертки в трансформер: пространственная сетка сохранена на уровне $H' = 16, W' = 128$, что дает $16 \times 128 = 2048$ визуальных токенов размерности $d_{\text{model}} = 256$.
3. Поставили блок внимания C2PSA (Pointwise / Position-Sensitive Attention с MultiheadAttention на 4 головы) для сбора глобального контекста формулы до проекции в декодер.
4. Добавили 2D синусоидальный позиционный эмбеддинг (2D PE: 128 каналов по X, 128 по Y).

**Результат**: декодер получил детальную карту признаков с высоким разрешением по горизонтали ($W'=128$), что позволило разделять мелкие индексы и сложные дроби.

### 3.5. Инверсия изображений: данные как ненулевой сигнал
В исходном датасете изображения стандартные: черный текст на белом фоне.  
**Проблема**:
1. Пиксели фона — белые ($255$, около $1.0$ после нормализации), а текст — черный ($0$).
2. В нейросетях со смещениями и функциями активации ReLU / SiLU нулевое значение тензора означает отсутствие сигнала, а положительные числа — наличие признака. Черный текст на белом фоне превращал символы в "дыры" на фоне сплошной активности.
3. При паддинге картинки на холст $1024 \times 128$ граница между белым фоном формулы (255) и черным нулем холста (0) давала паразитный перепад градиентов, ломавший свертки.  
**Решение**: инвертировали картинки при средней яркости $\bar{I} > 127$:

$$
I_{\text{inv}} = 255 - I
$$

Белый текст на черном фоне: фон стал строго нулем ($0$), идеально совпав с нулями холста, а линии формулы стали активным положительным сигналом ($> 0$).  
В cross-attention декодера добавили маску глифов:

$$
M_{\text{memory}} = \text{AdaptiveMaxPool2d}((X > 0), (16, 128))
$$

**Результат**: метрика **Macro-ECDM поднялась до 0.8 (79.29% - 80%+)**.

## 4. Функция потерь и регуляризация

### 4.1. Кросс-энтропия с Label Smoothing
Для срезания избыточной уверенности сети (overconfidence) целевое распределение сглаживается с $\epsilon = 0.1$:

$$
p_{\text{LS}}(k) = (1 - \epsilon) \cdot \mathbb{I}(k = y_t) + \frac{\epsilon}{|V|}
$$

Лосс на один токен:

$$
\mathcal{L}_{\text{CE}}(y_t, \hat{y}_t) = -\sum_{k=1}^{|V|} p_{\text{LS}}(k) \log \frac{\exp(z_{t, k})}{\sum_{j=1}^{|V|} \exp(z_{t, j})}
$$

### 4.2. Взвешивание редких токенов (Inverse Class Frequency)
Скобки `{`, `}` и базовые цифры встречаются на порядки чаще редких операторов. Веса классов считаются по обучающему сплиту:

$$
f_i = \frac{N_i}{\sum_{k \in V} N_k}
$$

$$
w_i = \min\left(\frac{1}{f_i + 10^{-5}} \cdot \frac{1}{\min_{j} \frac{1}{f_j + 10^{-5}}}, \; \text{weight\_ratio}\right), \quad w_{\text{pad}} = 0
$$

где $\text{weight\_ratio} \in [1.5, 5.0]$, а вес паддинга обнулен ($w_{\text{pad}} = 0$).

Итоговый лосс батча:

$$
\mathcal{L}_{\text{weighted}} = \frac{\sum_{b=1}^B \sum_{t=1}^T w_{y_{b,t}} \mathcal{L}_{\text{CE}}(y_{b,t}, \hat{y}_{b,t})}{\sum_{b=1}^B \sum_{t=1}^T w_{y_{b,t}} + 10^{-8}}
$$

### 4.3. Векторизованный штраф за зацикливание при обучении
Если в процессе обучения префикс генерирует токен чаще, чем он встречается в таргете, логит штрафуется квадратично прямо в графе:

$$
\Delta z_{b, t, v} = 2.0 \cdot \max\left(0, \sum_{\tau=1}^t \mathbb{I}(y_{b, \tau} = v) + 1 - \sum_{\tau=1}^T \mathbb{I}(\text{target}_{b, \tau} = v)\right)^2
$$

Все логиты жестко зажимаются в диапазон $[-60000.0, 60000.0]$ во избежание переполнения FP16 при AMP-обучении.

## 5. Синтаксические ограничения инференса

В инференсе (жадный поиск или Beam Search) логиты на каждом шаге $t$ модифицируются правилами грамматики TeX:

1. **Запрет пустых скобок**: если предыдущий токен $y_{t-1} = \text{"\{"}$, логит закрывающей скобки обрезается:

$$
z_{t, \text{"\}"}} \leftarrow z_{t, \text{"\}"}} - 1000.0
$$

2. **Штраф за дублирование открывающей скобки**: если $y_{t-1} = \text{"\{"}$:

$$
z_{t, \text{"\{"}} \leftarrow z_{t, \text{"\{"}} - 2.0 \cdot |z_{t, \text{"\{"}}| - 5.0
$$

3. **Баланс скобок**: если число закрытых скобок достигло числа открытых ($\sum \mathbb{I}(y = \text{"\}"}) \ge \sum \mathbb{I}(y = \text{"\{"})$):

$$
z_{t, \text{"\}"}} \leftarrow z_{t, \text{"\}"}} - 1000.0
$$

4. **Правила индексов**: после операторов `_` и `^` запрещены повторные операторы индексов и закрывающие скобки:

$$
z_{t, \text{"\_"}} \leftarrow -1000.0, \quad z_{t, \text{"\textasciicircum"}} \leftarrow -1000.0, \quad z_{t, \text{"\}"}} \leftarrow -1000.0
$$

5. **Подавление циклов**: если токен генерируется подряд $\ge 3$ раз:

$$
z_{t, y_{t-1}} \leftarrow z_{t, y_{t-1}} - 50.0
$$

### 5.1. Лучевой поиск (Beam Search) с нормализацией длины
Скор луча $Y$ длины $T$ нормализуется с экспоненциальным штрафом длины:

$$
\text{Score}(Y) = \frac{\sum_{t=1}^T \log P(y_t \mid y_{<t}, X)}{\left(\frac{5 + T}{6}\right)^{0.7}}
$$

## 6. Предобработка данных

### 6.1. Предобработка картинок
Входной тензор: $(1, 128, 1024)$.

**Инверсия цвета:** считаем среднюю яркость пикселей:

$$
\bar{I} = \frac{1}{H_{\text{orig}} \cdot W_{\text{orig}}} \sum_{i=1}^{H_{\text{orig}}} \sum_{j=1}^{W_{\text{orig}}} I_{i,j}
$$

Если $\bar{I} > 127$ (темный текст на светлом фоне), инвертируем:

$$
I_{\text{inv}} = 255 - I
$$

Фон становится 0, а глифы символов — активными значениями ($> 0$).

**Пропорциональный ресайз:** масштабируем с сохранением aspect ratio:

$$
s = \min\left(\frac{1024}{W_{\text{orig}}}, \; \frac{128}{H_{\text{orig}}}\right)
$$

Интерполяция — билинейная (`Image.BILINEAR`).

**Паддинг на холст:** вставляем масштабированную картинку в верхний левый угол нулевого холста $1024 \times 128$. Черный фон картинки бесшовно стыкуется с нулями паддинга.

**Нормализация:**

$$
\hat{X} = \frac{X / 255.0 - \mu}{\sigma}, \quad \mu = 0.0672, \; \sigma = 0.1625
$$

### 6.2. Словарь и спецтокены
Словарь токенов генерируется из очищенных формул с добавлением 4 служебных токенов:
- `<P>` — паддинг (pad token, ID = 0, вес в лоссе = 0)
- `<S>` — старт последовательности (sos token)
- `<E>` — конец последовательности (eos token)
- `<UNK>` — неизвестный токен (unknown token)

Токенизация регулярным выражением:

```regex
\\[a-zA-Z]+|\\[^a-zA-Z]|\d|[a-zA-Z]|[^ \t\n\r\f\v]
```

## 8. Запуск (CLI)

### 8.1. Установка окружения
- Python >= 3.10
- PyTorch >= 2.0 (CUDA)
- TeX Live / MiKTeX (опционально, для компиляции формул в PNG)

```bash
pip install -r requirements.txt
```

### 8.2. Подготовка датасета
```bash
python scripts/prepare_data.py --source_dir ./dataset/dataset --target_dir ./dataset/dataset_clean
```

### 8.3. Обучение
```bash
python scripts/train.py --model_name real_test_model --base_path ./dataset/dataset_clean --num_epochs 150 --lr 1e-4 --weight_ratio 5.0 --label_smoothing 0.1
```

### 8.4. Оценка чекпоинта
```bash
python scripts/evaluate.py --checkpoint ./checkpoints/best_real_test_model.pt --base_path ./dataset/dataset_clean --beam_width 3 --num_visual_samples 10
```

### 8.5. Инференс картинки
```bash
python scripts/infer.py --image ./test_sample.png --checkpoint ./checkpoints/best_real_test_model.pt --beam_width 3 --render ./pred_render.png
```
